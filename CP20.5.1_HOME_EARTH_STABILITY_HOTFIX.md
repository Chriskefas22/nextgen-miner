# CP20.5.1 — HOME EARTH STABILITY HOTFIX

Purpose:
Fix the mobile 500/system-error regression while keeping the Landing Earth
engine as the visual foundation for Home.

## Why this is needed

The current Home Earth implementation creates a WebGL context manually, then
constructs Three.js and browser-only Canvas/UI effects. On some mobile
browser/WebView combinations, an exception during initialization/render can
surface through the application error boundary even though Vercel build logs
remain green.

This hotfix makes the renderer fail-safe.

## Replace exactly

- `components/home/HolographicEarth.tsx`
- `components/home/HolographicEarth.module.css`

No change is required to `HomeCommandCenter.tsx`.

## Important design decisions

- Reuses the frozen Landing Earth texture:
  `/assets/landing/earth-equirectangular.webp`
- Keeps Three.js as the renderer already present in package.json.
- Uses WebGL Earth + atmosphere + surface nodes + network routes + orbital
  rings + platform.
- N Core is CSS/HTML, avoiding fragile browser canvas text APIs.
- Full renderer initialization is protected by try/catch.
- Render loop is protected by try/catch.
- Missing/unsupported WebGL falls back to a CSS holographic Earth.
- Texture load failure falls back instead of crashing Home.
- Mobile uses reduced sphere segments and pixel ratio.
- `prefers-reduced-motion` is respected.
- Supabase/economic logic remains untouched.
- LandingPage and Landing NetworkCore remain untouched.

## Manual install

1. Replace the two files above in GitHub `main`.
2. Do not replace `components/landing/NetworkCore.tsx`.
3. Do not delete `/public/assets/landing/earth-equirectangular.webp`.
4. Push to `main`.
5. Wait for Vercel production deployment.
6. Hard refresh `/dashboard`.
7. Test Android first, then desktop.
8. Verify the Home opens even when WebGL is unavailable.
9. Verify the Earth rotates, nodes pulse, routes move, and platform/orbits animate.
10. Verify asset/status/hashrate metrics still reflect Home/Supabase.
